The Green-Signal Audit

Most audits look for what is broken. This one looks for something narrower and harder to see: guarantees whose enforcement is narrower than their claim — the check that passes over ground it never visited. A pass and a never-looked are the same byte.

What this is

We ran this method against our own substrate and left the failures in — including the ones we caused. An audit of ourselves is a harder credential to fake than an audit of a stranger.

The system under test is a working AI-engineering substrate: about fifty repositories, thirteen production containers, twenty-three scheduled routines, roughly nine hundred records, and six independent monitors that run on every session start. Every one of those monitors reported healthy on the morning of the audit.

Findings were produced in a single day by six read-only verification agents working in parallel, one per subsystem, each instructed to re-measure rather than trust the record. Nothing below was discovered by a failing test or a red alarm, because there weren't any.

What we actually look for

A check sits on one of five rungs. It must sit one rung above the claim it is defending. Level with the claim is a restatement; below it is a lie with a green tick. Most real defects are exactly one rung too shallow.

  • 01The tokenDoes the string appear anywhere?
  • 02The behaviourIs the thing actually being done?
  • 03The domainWhat does this guarantee's scope genuinely admit?
  • 04The shapeCan it be wrong again, or is the failure now impossible?
  • 05The instrumentIs the measurement measuring? Has it been tested against a known answer?

The difficulty is that each rung is invisible from inside the ones below it. A word match looks exactly like a behaviour check. An unrun check is byte-identical to a pass. You cannot audit your own rung from the inside — which is the entire argument for an external pass.

Findings

Ordered by how badly each one misdirected the work. Every finding is verifiable on the machine in under a minute — that is the standard, not a courtesy.

01

A claim dated “today”, written ten days earlier

The signal

The highest-authority row in the disposition register — priority item one — carried the evidence marker (evidence: today).

The ground

Written ten days before. A relative word frozen into a file cannot age. It doesn't go stale — it reads fresh forever, which is strictly worse, because a visibly old date at least invites the check.

Why it mattered: it was the freshest-looking line in the file and the only one that was structurally incapable of being true.
02

An item marked open for eleven days after it closed

The signal

A production permanence issue listed as outstanding: the fix lived in a running container but not in the image, so a restart would lose it.

The ground

The image had been rebuilt eleven days earlier and the container recreated 11.5 seconds later. docker diff showed no in-container source edits at all. It was fixed the whole time.

Why it mattered: sessions kept sequencing work around a solved problem, and a real new gap — the production source existed in no version control anywhere — sat underneath it, unnamed.
03

“One key away” was five acts away

The signal

The revenue service was recorded as one credential away from its first customer. 338 tests green. Delivery, retention and webhook handling all built and scheduled.

The ground

The service was deployed nowhere. Its deploy config had never been applied, the hosting CLI was logged out, nothing was listening on any port, and no mail transport was configured. A customer had no reachable address to buy from.

Why it mattered: a green suite over a service with no address. The tests were honest about the code and silent about the deployment, and nothing in the system was responsible for noticing the difference.
04

A working copy vanished and nothing noticed

The signal

A project listed at a known local path, with a monitor watching that path for drift.

The ground

The directory had been removed in a desktop reorganisation. Every recorded address was dead. The monitor reported the repository “unscannable” — which read as a configuration nuisance, not as loss.

Why it mattered: the only surviving copy was a remote push from nine days earlier. Had that push not happened, the work was gone and the alarm for it was a shrug.
05

Seven repositories existed in exactly one place

The signal

A loss-risk policy tracked local-only repositories and confirmed each had an off-machine mirror. All green.

The ground

The policy's domain was local-only. Seven repositories were the mirror image — remote-only, never cloned, never mirrored — and were invisible to a check that only ever looked in one direction.

Why it mattered: textbook narrow-domain. The guarantee said “no single-copy repositories”; the enforcement said “no single-copy local repositories”; the difference was seven.
06

A blocker that had never existed

The signal

An infrastructure note instructing the next engineer to create missing SSH host aliases before working on two servers.

The ground

The aliases existed and both hosts authenticated on the first attempt.

Why it mattered: phantom blockers are more expensive than real ones. Real blockers get solved; phantom ones get routed around, permanently.
07

Two services recorded live were down

The signal

A service inventory listing local inference ports as part of the running stack.

The ground

Two of them answered nothing. A third, listed with a caveat, was the only one actually up.

Why it mattered: the inventory was written once and read continuously. Nothing re-probed it, so it aged into fiction one port at a time.
08

A pin that had outgrown its own scope

The signal

365 files pinned to local disk so builds could not be broken by cloud-sync eviction. Verified at the time and correct.

The ground

The tracked set had since grown to 1,383 files. The original 365 pins held perfectly; 176 newer files were eviction-eligible. A pin is a snapshot, not a policy — and nothing re-ran it.

Why it mattered: the check was true about the files it covered and silent about the ones added after. Fixed by re-pinning all 1,383, zero errors.
09

Counts that were stale the day they were written

The signal

A handoff document recording a test suite at 846 passing.

The ground

The commit it cited already said 861. Measured on audit day: 890. Two other headline numbers in the same document were also stale within hours of being written.

Why it mattered: not the numbers — the practice. Frozen counts in a living document decay silently, and every reader downstream inherits a false baseline.
10

A backup gate that verified the wrong property

The signal

Nightly off-site backups gated by an integrity check. Exit zero every night.

The ground

The check verified the archive's internal self-consistency, never that it could actually be restored. Those are different properties, and only one of them is what a backup is for.

Why it mattered: replaced with a real test-restore into a temporary location, HEAD compared, then discarded. Proven both ways — a real run at exit zero, and a deliberately truncated archive correctly reported bad.

The three we caused ourselves

These are in the report because leaving them out would make it a brochure. All three are defects in the instrument built to find the other ten — discovered on its first day, by using it.

11

The new instrument flagged decisions as failures

The signal

First run: 19 items past their re-verification window. Alarming, and apparently vindicating.

The ground

Six were correct. They were deliberately parked items, and parked things are supposed to age. The check measured a date's age (rung 2) beneath a claim about actionability (rung 3) — the exact error it was built to catch.

Why it mattered: a monitor that reddens a deliberate decision teaches its reader to ignore it, and the ignored monitor is the one that was right the seventh time. Findings went 48 → 13 once the scope was fixed.
12

It caught its author documenting a fix instead of making one

The signal

Four long-open questions were researched, answered, and written up in a detailed resolution block. The work was real and the answers were correct.

The ground

The finding count didn't move. The original rows still said unresolved — the answers had been appended beside them, not applied to them. Anyone reading the register in the normal order would still have hit the stale rows first.

Why it mattered: the most honest moment of the audit. Recording a fix and making one feel identical from the inside, and only an external count told the difference. Rewriting the rows dropped it 8 → 4.
13

Two mutation tests were inert, and passed

The signal

Three mutations run against the new instrument's test suite to prove the tests could fail. All three reported caught.

The ground

Two attempts had been mangled by shell escaping into a regex that could never match — a literal control character where a word boundary was intended. The mutation never applied. A mutation that doesn't apply is byte-identical to one that's caught.

Why it mattered: this is the thesis eating itself, and it is the reason the method is worth paying for. Verified afterwards by in-memory injection with the anchor asserted present. The test does have teeth — but that was luck until it was checked.

One day later — the class became an instrument

Finding 13's failure mode — an escape interpreted at write time, leaving a file byte-different and text-identical — was turned into a permanent detector the next morning: a byte-level scan of every git-tracked text file, run on every session start. Its first pass covered 10,453 files across 44 repositories and found 19 control characters that no parser, compiler, grep, or diff had ever objected to. Two of them were live bugs in production code.

14

Two production regexes could never match — and the compiler was clean

The signal

A code-intent classifier and an @-mention route, both shipped, both type-checked clean, both apparently working in production.

The ground

The \b word boundaries in both were literal backspace bytes (0x08). One regex was dead on both ends of its alternation; the mention route's first branch was dead — the feature looked alive because two later alternatives still matched. Proven by behaviour, not compilation: the repaired regex returns true on the text it was written to catch; the original returns false.

Why it mattered: the defect class is invisible to every text-level tool — tsc, review, grep and diff all agreed the code was fine. Only the raw byte differs, so the raw byte is what the instrument reads.
15

The new detector carried the report's own defects — and its tests caught them

The signal

The detector shipped with a green test suite, including a mutation test proving one invisible byte separates pass from fail.

The ground

An unreadable scan root printed “no findings, exit 0” — absence-as-completion, inside the tool built to catch it — and the first version of its cache test was itself mangled by the exact class under test: a shell heredoc ate a backslash level, so the “clean” fixture wasn't. Both caught before commit — by the suite, not by care.

Why it mattered: you cannot audit your own rung from the inside — but a suite designed to be able to fail can. The instrument's green is only worth what its ability to go red has been proven to be.
